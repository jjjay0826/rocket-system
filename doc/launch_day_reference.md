## 🔴 第一部分:出門前必做(做不到就別飛)

### 1. 三個編譯開關的狀態

| 開關 | 位置 | 現在 | 飛行前必須 |
|---|---|---|---|
| `REMOTE_CMD_UNRESTRICTED` | `main.c:774` | ✅ **已關** | 保持關閉 |
| `PYRO_ADC_FITTED` | `main.c:181` | ✅ **已關** | 保持關閉(分壓**沒有**焊) |
| `LORA_MODE_PINS` | `lora_e22.c:49` | ✅ **已關** | 保持關閉(M0/M1 **還接在 GND**) |
| `LORA_USE_AUX` | `lora_e22.c:71` | ✅ 開 | 維持(AUX→PB9 已接,現場確認) |

**⚠ 2026-08-01 更正:本表在此之前有兩行是錯的。**
舊版寫 `PYRO_ADC_FITTED` 與 `LORA_MODE_PINS`「✅ 開,維持」,理由是
「2026-07-27 分壓已焊/M0M1 已改線」—— **兩項硬體改動實際上都沒有做**。
照舊表操作會在發射台上做出錯誤決定,所以三個開關已全部關閉。

**關閉的理由**

- **`REMOTE_CMD_UNRESTRICTED`**:開著時遠端開傘沒有任何閘門 —— 不需要 ARM、
  不管飛行狀態、可無限重複點火。那是桌測用的。
  關閉後恢復三道閘門:IDLE 需先 ARM、離架後 10 秒內拒收、已開傘/已落地拒收。
  **編譯時不再噴 `#warning ... NOT FLIGHT SAFE`,那行消失才算真的關掉。**

- **`PYRO_ADC_FITTED`**:分壓沒焊,PB0/PB1 讀到的是浮接雜訊(0.0~0.5V)。
  而 5.0V 以下就判定「保險絲熔斷」→ **等於永久謊報一個最該告警的故障**。
  關掉之後 `v_fuse`/`v_arm` 維持 `-1`,遙測送 -1 =「沒有量測能力」,
  與「量到 0V＝真的熔斷」明確區分。

- 🔴 **`LORA_MODE_PINS`**:M0/M1 還硬接在 GND,而韌體把 PB7/PB5 設成**推挽輸出**。
  平常寫 LOW 無害,但 **`/setch` 會把兩支同時拉 HIGH 200~700ms** ——
  3.3V 直接短路到地,輸出級 R_ds(on) 約 25~50Ω → **每支腳約 82mA,
  而 STM32F411 單腳絕對最大值是 25mA(超標 3.3 倍)**。
  而且換頻根本不會成功:模組端 M0/M1 實體仍是 0,從沒進設定模式。
  **關閉前絕對不要打 `/setch`。**

⚠ **兩塊板都要燒同一個設定。**

### 2. 燒錄後立刻接 USB 檢查開機報告

```
MOD: BMP=1 IMU=1 LORA=1  REF_PRESS=1013.25 hPa  CLK=HSE  RST=POWER-ON  VF=-1.00V VA=-1.00V
```

| 欄位 | 正常 | 不正常代表什麼 |
|---|---|---|
| `BMP=` | 1 | 0 = 氣壓計沒起來,開傘條件 A 失效 |
| `IMU=` | 1 | 0 = 慣性感測沒起來,開傘條件 B 失效 |
| `LORA=` | 1 | 0 = **模組沒回應**,整場收不到遙測 |
| `REF_PRESS=` | 950~1030 | 超出 = 氣壓計讀值有問題 |
| `CLK=` | **HSE** | `HSI-FB` = 晶振故障已降級,**板子要查** |
| `RST=` | POWER-ON | `BROWNOUT` = 電源瞬斷(接觸不良/撞擊)<br>`IWDG` = 看門狗(異常)<br>`NRST-PIN` = 有人按了重置 |
| `VF= / VA=` | **7~8.4V** | -1.00 = ADC 沒啟用(分壓已焊,不該再看到 -1)<br>接近 0 = **保險絲熔斷** |
| 若出現 `BUS=CLAMPED!` | 不該出現 | SPI2 匯流排被鉗位,**立刻斷電查線** |
| 若出現 `UNRESTRICTED MODE` | 不該出現 | **不能飛,回去關開關** |

**兩塊板都要各自檢查一次。**

### 3. 電火頭安全程序

規範 4.6:儲能裝置在有人靠近時必須有**兩個獨立事件**擋著。

- **整備/搬運/上架**:啟動開關 OFF(或點火線未接)= 安全狀態
- **人員撤離後**、依審查委員指示才武裝
- **武裝動作必須從遠處做**(拉繩拔銷/長桿),不可用手在箭體上接線
- 武裝後**任何人不得靠近火箭**

## 第二部分:地面站啟動

### 開機順序

```
1. 先插好兩個 LoRa dongle(915MHz 和 2.4GHz)
2. 確認 settings.json 的 COM 埠對得上(見下)
3. 雙擊 run_persist_backend.bat   ← 最常用:同時起後端+GUI
```

| 檔案 | 用途 |
|---|---|
| `run_persist_backend.bat` | **標準啟動**:後端常駐 + GUI,GUI 關掉後端還在 |
| `run_gui_only.bat` | 只開 GUI,接到已經在跑的後端(GUI 崩潰後重開用) |
| `run_backend_ch1.bat` / `ch2.bat` | 只開單一頻道後端(除錯用) |

### COM 埠設定

檔案 `settings.json`,現在是:

```json
ch1 → com11 @ 9600     (915MHz  E22)
ch2 → com7  @ 9600     (2.4GHz  E28)
```

**COM 號換插孔就會變。** 開機發現對不上,兩個辦法:
- 改 `settings.json` 後重開
- 或 GUI 裡打 `/port COM12`(只改焦點頻道,即時生效)

⚠ **兩個頻道絕對不能設同一個 COM 埠**——序列埠是獨佔的,設一樣會有一塊板無聲失聯。

## 第三部分:所有指令

在 GUI 最下方的命令列輸入,**必須以 `/` 開頭**。打 `/help` 可以隨時叫出清單。

### 連線類

| 指令 | 作用 |
|---|---|
| `/port <COM>` | 換焦點頻道的序列埠,例 `/port COM12` |
| `/baud <數字>` | 換鮑率(正常都是 9600) |
| `/connect` | 重新連線 |
| `/disconnect` | 停止序列通訊 |
| `/focus <ch>` | 切換焦點頻道,例 `/focus ch2` |

### 資料類

| 指令 | 作用 |
|---|---|
| `/reset-angle` | 地面端姿態歸零(火箭平放時做) |
| `/reset-data` | **開新的一場**:舊 CSV/log 封存,開新檔,畫面全清 |

### 校準類

| 指令 | 作用 |
|---|---|
| `/cal` | 焦點板氣壓歸零 + 地面姿態歸零 |
| `/cal_all` | **全部板**氣壓歸零 + 地面姿態歸零 ← 發射台上用這個 |

⚠ 只在 IDLE 受理,飛行中火箭會拒收。

### 🚨 緊急類(火工品)

| 指令 | 作用 |
|---|---|
| `/arm` / `/arm_all` | 遠端解鎖,**30 秒**視窗 |
| `/dpl` / `/dpl_all` | 強制開傘 |
| `/abg` / `/abg_all` | 開氣囊 |

**帶 `_all` 的會同時發給兩塊板,緊急時一律用 `_all`。**

### 換頻(硬體改線後才能用)

| 指令 | 作用 |
|---|---|
| `/setch <0-80>` | 換 LoRa 頻道,頻率 = 850.125 + ch (MHz) |

**合規頻道只有 CH70~74**(920~925MHz)。現用 **CH72 = 922.125MHz**。
撞頻時的順序建議:**CH73 → CH71 → CH74**(CH70 貼著法規邊界,最後才用)。

⚠ **火箭換頻後,地面端 dongle 必須跟著換,否則該板立刻失聯。**

### ARM 到底在管什麼（2026-08-01 補寫）

`ARM` 做三件事，然後就開始倒數：

```c
manual_arm_code = HAL_GetTick() % 10000;   // 隨機四位數，每次都不同
manual_arm_time = HAL_GetTick();           // 起算
manual_armed    = 1;
```

火箭回：`MSG INFO MANUAL ARMED - FIRE 0473 within 30s (SAFE aborts)`
**那個四位數只有這一次有效，而且只有你看得到**（走你的 LoRa 頻道回來）。

#### 窗口長度是動態的

| 狀態 | 窗口 | 為什麼 |
|---|---|---|
| `IDLE`（地面） | **30 秒** | 防「ARM 完就分心」——發射台上有人站在旁邊 |
| 飛行中（≠IDLE） | **300 秒** | 緊急時「單發 `FIRE <碼>`」就開傘（1~2 秒），<br>不必在下墜的十幾秒裡跑完兩步 |

★ 地面 ARM 之後火箭起飛，窗口會**自動延長成 300 秒**（判斷式看的是當下的
`flight_state`，不是 ARM 當時的）。這是刻意的：飛行中 armed 待命正是備援
要的狀態。

#### 🔴 兩條開傘路徑，只有一條需要 ARM

| 路徑 | 需要 ARM？ | 完整條件 |
|---|---|---|
| **`FIRE <碼>`**（USB／手打） | ✅ **一定要** | ① 已 ARM<br>② 窗口未逾時<br>③ **四位數碼完全相符**<br>④ 不是 DEPLOYING／DEPLOYED<br>⑤ 不是 LANDED |
| **`/dpl`**（地面站，`#CMD:FORCE_DPL_SALT9981#`） | **只在 IDLE 要** | · IDLE → **必須先 ARM**（桌測解鎖）<br>· 飛行中 → **不必 ARM**，改由三道閘門擋：<br>　　離架後 10 秒內拒收（上升段誤開＝解體）<br>　　已 DEPLOYING／DEPLOYED 拒收<br>　　已 LANDED 拒收 |
| **PB6 實體鈕** | ✅ 要，還要更多 | IDLE **且** ARM **且** GNDTEST 三者齊備 |

**為什麼 `/dpl` 飛行中不要 ARM**：那是唯一的緊急救援手段，而且它的秘鑰
字串本身就是驗證（24 字元，同頻他隊或雜訊發不出來）。要求兩步會在最需要
它的時候多花 0.7 秒×2。

#### 什麼會讓 ARM 失效

| 觸發 | 位置 |
|---|---|
| 窗口逾時 | `ManualDeploy_Poll` 每輪主迴圈檢查 |
| **`SAFE` 指令** | 立刻解除，回 `MANUAL SAFE (disarmed)` |
| `FIRE` 成功點火 | 點完就解除，不會連發 |
| `FIRE` 碼過期／已開傘／已落地 | 一併解除，強迫重新 ARM |
| 遠端 `/dpl` 成功 | 解除 |

★ **`FIRE` 打錯碼【不會】解除 ARM** —— 只回 `wrong code`，窗口繼續。
打錯字不用重來。

#### 地面站上怎麼看

狀態列會顯示 `🔓ARMxx s` —— **那是火箭回讀的倒數**，不是地面站自己算的。
看不到它就代表 ARM 沒有真的送達。

### 點火鈕的兩段式保險

1. **第一次按** → 變紅、文字變「確認?」、開始 **3 秒倒數**
2. **3 秒內再按一次** → 才真的發射
3. **300ms 內的連按會被忽略**(防手抖/雙擊)
4. **3 秒沒有第二次按** → 自動解除

按鈕寬度是鎖死的,按下去**位置不會移動**,第二下不會誤點到旁邊。

## 第五部分:狀態燈與符號

### 每塊板的 LED(左下角)

| 顏色 | 意思 | 該做什麼 |
|---|---|---|
| 🟢 **綠** | 正常收資料 | — |
| 🟠 **橙(常亮)** | 後端在跑,還沒收到遙測 | 等/查天線/查火箭有沒有開 |
| 🟡 **黃(閃)** | **有資料流入但全部解析失敗** | **查裝置插對沒、鮑率對不對、頻段對不對** |
| 🟠 **橙(閃)** | 資料變舊(1.5~5 秒沒新資料) | 訊號變弱,注意 |
| 🔴 **紅** | 超過 5 秒沒資料 | RF 中斷 |
| 🟣 **紫(閃)** | 後端服務沒啟動 | 跑 `run_persist_backend.bat` |

**黃燈是最容易被誤解的**:它代表訊號有進來但看不懂,通常是**插錯 dongle**或**鮑率設錯**,不是天線問題。

### 狀態列符號

```
▶ch1 com11 ✔0.3s 🔒7.9V    ch2 com7 ◌無資料
```

| 符號 | 意思 |
|---|---|
| `▶` | 這是焦點板,單板指令會打到它 |
| `✔0.3s` | 正常,0.3 秒前收到資料 |
| `⚠2.1s` | 資料變舊 |
| `✖8s` | 失聯 8 秒 |
| `◌無資料` | 還沒收到過 |
| `⚠格式錯` | 有資料但解析失敗 |
| `🔓ARM28s` | **該板已武裝**,還剩 28 秒 |
| `🔒7.9V` | pyro 電源正常、未武裝(要 ADC 焊好才有) |
| `🔓武裝7.9V` | pyro 已武裝 |
| `🔴熔斷` | **保險絲斷了,這塊板點不了火** |

### 開傘確認訊息

| 訊息 | 意思 |
|---|---|
| `✅ [CONFIRMED] ch1 DPL verified` | **火箭確實收到並執行了** |
| `🚫 [ch1] DPL REJECTED by rocket: ...` | 火箭收到但拒收(後面會寫原因) |
| `🔴 [UNCONFIRMED] ch1 DPL 已送出但 10s 內未見下行確認` | **沒有任何回應**,可能上行中斷 |

**看到 UNCONFIRMED 不要慌**:另一塊板若正常,單傘仍可安全著陸。可以重發,但**不要因為單板未確認而中止任務**。

## 第六部分:飛行狀態機

```
IDLE(0) ──離架偵測──► LAUNCHED(1) ──開傘判斷──► DEPLOYING(2) ──1秒──► DEPLOYED(3) ──靜止──► LANDED(4)
```

| 狀態 | 顯示 | 意思 |
|---|---|---|
| 0 IDLE | 地面靜置 | 等待離架 |
| 1 LAUNCHED | 飛行中 | 監視高度與時間 |
| 2 DEPLOYING | **開傘訊號輸出中** | GPIO 拉高 1 秒 |
| 3 DEPLOYED | 開傘完成 | 等待落地 |
| 4 LANDED | 已落地 | 低功耗記錄(終點,不會再變) |

### 地面站畫面上的 11 列是怎麼來的

火箭只有 5 個狀態,但畫面列了 11 列 —— **其餘 6 列是地面站從遙測推導的**,
用不同底色與「推導」二字標示,不會和火箭回報混在一起。

**火箭回報(綠底,ST 欄直接來)**

| 列 | ST | 韌體怎麼判 |
|---|---|---|
| `IDLE` | 0 | 開機預設 |
| `LAUNCHED` | 1 | 合加速度 ≥ 2.5g **持續 200ms**(100Hz 下連續 20 筆) |
| `DEPLOYING` | 2 | `(A ∧ B) ∨ C` — 見下一節 |
| `DEPLOYED` | 3 | DEPLOYING 之後 1 秒(`DEPLOY_PULSE_MS`) |
| `LANDED` | 4 | \|total_g−1\|<0.15 **且** rel_alt<30m,**持續 10 秒**<br>★兩半都要有活著的感測器背書,否則不判定 |

**地面站推導(淡藍底,標「推導」)**

| 列 | 依據 | 規則 |
|---|---|---|
| `ARMED` | 下行 MSG | 收到 `MANUAL ARMED` —— 是火箭的**回讀**,不是地面站送出指令的時刻(規範 4.6.7 要的就是回讀) |
| `IGNITION` | 遙測 `GA` | **ST:0 期間只記候選**(最後一次由下往上穿過 1.5g),**等 ST 變 1 才定案**。★火箭自己看不到點火(要 2.5g×200ms,那時已過約 1.3 秒),但遙測一直在送,地面站看得到推力爬升 —— 這是量到的,不是拿常數回推。<br>★**不能在 ST:0 就定案**:那是整段待命時間,搬上架/放下/撞到/陣風都會超過 1.5g,而推導是一次性的,誤標就再也蓋不掉。<br>候選距離離架超過 5 秒不採信 —— 寧可空著也不標編出來的時間 |
| `BURNOUT` | 遙測 `GA` | ST:1 期間 `GA < 1.15`(且先看過 `GA > 1.5`)。與韌體同一門檻 |
| `COASTING` | 同 BURNOUT | 同一刻。時間戳相同**不是冗餘** —— BURNOUT 是「推力沒了」,COASTING 是「開始純靠慣性」,報告書要分開講 |
| `APOGEE` | ST 轉 2 | 進入 DEPLOYING 的那一刻,峰值已經確定。標籤帶高度 |
| `TOUCHDOWN` | 遙測 `VZ` | ST:3 期間 \|vz\| 從 >3 掉到 <1。**★這不等於 LANDED** —— LANDED 要靜止 10 秒,也就是觸水後 10 秒。落海要記的是**觸水點**,不是十秒後漂走的位置 |

**時間軸**

- **T0 = `LAUNCHED`**(離架),不是點火、也不是開傘
- **用火箭自己的時鐘**(遙測 `T` 欄的 uptime),不是地面站收到封包的時間 ——
  否則鏈路延遲與 GUI 延遲會被算進 T+
- 遙測 2Hz → **時間解析度就是 0.5 秒**,而且 T0 最多晚半包,所以之後每一格

### 開傘條件 `(A ∧ B) ∨ C`

| 條件 | 內容 |
|---|---|
| **A** | 氣壓高度低於最高點 10m(且最高點需 ≥20m) |
| **B** | 垂直速度持續向下 1.5 秒 |
| **C** | **離架後 18 秒**無條件強制開傘(備援) |

- A∧B 同時成立 = 頂點後確認下降,**最精確**
- C 單獨成立 = 感測器故障時的保底

### 為什麼只怕東風

回收區極度不對稱:**東邊 +2812 m,西邊只有 −52 m**。東風把火箭吹向西邊的陸地。

**每 1 m/s 東風把落點往西推 82~131 公尺**,而無風落點才 +365~571 m。

| 東風(模擬中的均勻風) | 落西界以西 | 落**發射台**以西 |
|---|---|---|
| 3 m/s | 0 / 9 | 0 / 9 |
| **4 m/s** | 0 / 9 | **1 / 9** |
| 4.5 m/s | 1 / 9 | 4 / 9 🔴 |
| 5 m/s | 3 / 9 | 7 / 9 🔴 |
| 6 m/s | 8 / 9 | 9 / 9 |

**落在發射台後方比出界更嚴重**——那裡是人員位置。4.5 m/s 就有 4/9 會這樣。

### 反直覺:推力越大、仰角越垂直,越容易回陸地

```
T090  頂點 835m   飛行 146s   臨界東風 5.0 ~ 6.0 m/s
T100  頂點1008m   飛行 173s   臨界東風 4.7 ~ 5.7 m/s
T110  頂點1183m   飛行 201s   臨界東風 4.0 ~ 5.1 m/s  ← 最危險
```
(區間的兩端是仰角 81° 與 79°)

飛得高 → 傘下時間長 → 風吹得久。**在 ±1° 公差內,寧可偏低(79°)不要偏高。**

### 箭身彎曲:方向是你可以控制的

仰角每偏 1° → 落點移動約 **46 公尺**。箭身接合處彎曲 β 度,效果等同飛行方向偏 β 度。

```
向西偏 2.0°  → 1/9 出界（在 8/1 的預報風況下）
向東偏 3.0°  → 最遠 1078m，東界 2812m，完全安全
```

**上架前把火箭放平在直的參考面上轉一圈,量出彎向哪一側,做記號,上架時朝【東】。**
零成本,而且比「想辦法把箭身弄直」實際得多。

### 南北風不用擔心

每 1 m/s 只推 90~147 m,要出南北界(±1890 m)需要 **13~21 m/s** 的風——那種風不會放行。
