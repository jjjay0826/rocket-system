# 2026-08-01 旭海 · 主傘失效原因分析

**結論先講 —— 這是一條因果鏈，不是單一原因：**

```
拖曳傘展開時把整個箭體帶動自旋（實測 1166 °/s = 3.2 轉/秒）
        ↓
主傘在自旋中充氣，傘繩扭轉，載荷【不再平均分給 8 條線】而集中到少數幾條
        ↓
受力最大的那條所在的傘布結構失效（撕裂）
        ↓
主傘永久失去阻力，成為飄帶。終端阻力 = 只剩拖曳傘
```

**自旋是量到的**（兩塊獨立航電板，不是推論）。**撕裂是推論**，但由兩條獨立證據
支持：扭轉在 T+22 就鬆開了而傘卻永遠沒恢復阻力（→ 損傷是永久的），以及終端
阻力精確等於「只有拖曳傘」（→ 主傘貢獻字面上的零）。

另外還存在一個**與這條鏈無關的獨立設計問題**：這副主傘在「直接跟著拖曳傘開」的
任何速度下滿開，載荷都會超出結構能承受的範圍。

證據全部來自兩塊獨立航電板的 2 Hz 遙測 ＋ TASA 直播存檔的 59.94 fps 影像。
箭體未回收（僅尋回鼻錐），無實體佐證。

## 0　時間軸基準

兩塊板各自以「自己判定離架」為 t=0，**ch1 比 ch2 晚 0.49 s 判定**。
本文一律換算到 **ch2 的 t_rel**，它同時也是影像的 T+。ch1 的原始 t_rel 需 +0.49。

對齊方法是地面站 log 的 UTC 前綴，不是擬合。對齊後兩板在事件前的取樣點
相差穩定的 30 ms，證明對齊正確。

## 2　核心證據：滾轉

### 2.1　軸向確認

推力段 `ax = −5.65 g`、`ay ≈ az ≈ 0`，所以 **X 是箭體長軸，gx 就是滾轉率**。

兩塊板在點火前都讀到 `gx = +17 °/s`（同號同量值），證明兩板的 X 軸定義一致，
後續的**正負號比較是有意義的**。

### 2.2　滾轉率歷程

| ch2 T+ | ch1 gx | ch2 gx | 橫向 (gy,gz) |
|---|---|---|---|
| 16.50 | +15.5 | +15.4 | 小 |
| 17.00 | **+49.8** | **+67.7** | 7 / 15 —— **純滾轉，不是翻滾** |
| 17.50 | **−100.0** | **−114.7** | 110 / 110 —— 開始擺盪 |
| 18.04 | **−463.9** | （跳拍） | 524 |
| 18.52 | （已失聯） | **+991.5** | 612 |
| 19.01 | — | +881.2 | 71 |
| 20.51 | — | −194.8 | 90 |
| 21.01 | — | +224.1 | 62 |

三點必須看清楚：

**① 滾轉在任何大載荷之前就開始了。**T+17.00 滾轉已達 50–68 °/s，
但 GA 只有 0.41/0.92 g。所以**不是開傘衝擊造成旋轉，是旋轉先於開傘**。

**② 是純滾轉，不是箭體翻滾。**T+17.00 的橫向角速度只有滾轉的 1/5～1/7。
翻滾會表現在 gy/gz，這裡沒有。所以扭矩是繞長軸的，來源是**已放出的回收系統
硬體**，不是箭體氣動失穩。

**③ 方向反覆反轉。**+17 → +68 → −115 → −464 → **+992** → +881 → −195 → +224。
穩定自旋不會這樣。**方向交替 ＋ 峰值 1166 °/s（3.2 轉/秒）＝ 懸吊系統變成了
一個扭轉振盪器** —— 傘繩被扭緊、儲能、反彈、再往另一邊扭緊。

> **不能宣稱的事**：累積扭轉圈數。2 Hz 取樣一個方向會在半秒內翻轉的訊號，
> 積分出來的數字沒有意義。可以確定的只有**瞬時峰值 1166 °/s** 和**方向反轉**
> ——這兩者都是單點瞬時讀數，不受取樣率影響。

## 3　為什麼判定終點是「結構失效」而不只是「可逆的扭轉束口」

自旋本身是量到的，沒有爭議。問題是它導致的終局是**可逆的束口（squidding）**
還是**不可逆的結構破壞**。兩條獨立證據指向後者。

### 3.1　扭轉鬆開了，傘卻沒有回來

| ch2 T+ | 滾轉率 | 說明 |
|---|---|---|
| 19.01 | 885 °/s | 主傘充氣後 |
| 20.51 | −215 | |
| 22.02 | −54 | |
| 22.5 以後 | ±20～150 交替 | **正常的鐘擺擺盪，不是持續扭轉** |

**到 T+22 扭轉已經解掉了。**但 T+22～43.6 的下降率完全平直，維持 32 m/s，
21 秒內沒有任何恢復跡象。

被扭轉束住的傘，扭轉一鬆就會恢復部分阻力 —— **它沒有。所以損傷是永久的。**

### 3.2　終端阻力精確等於「只有拖曳傘」

```
穩定下降段（T+24~43.6，40 點最小平方）
  下降率           32.1 m/s
  終端 CdA         0.426 m²
  主傘設計 10.4 m² →  4.1%
  若全部來自十字拖曳傘 (Cd=0.65)：等效布面 0.81 m 見方
```

0.81 m 見方正是一副合理的拖曳傘尺寸。被束口的傘通常仍有滿開的 10～30%，
**主傘貢獻的是字面上的零**。

### 3.3　為什麼「載荷太低不足以撕裂」這個反駁不成立

峰值量到 1.40 kN，而一副 10.4 m² 傘的 8 條繩合計額定約 8～20 kN。
乍看差一個數量級，撕不動。但這個論證有兩個漏洞，第二個是致命的：

1. **1.40 kN 是 2 Hz 取樣的下限。**開傘衝擊只有 50～150 ms 寬，
   500 ms 取樣抓到的是峰值的一部分。
2. **★ 傘在 1000 °/s 自旋、傘繩正在扭轉時，載荷不會平均分給 8 條線。**
   扭轉與不對稱充氣會把載荷集中到少數幾條上。平均看來撐得住的載荷，
   單條可以是平均的數倍。

換句話說：**陀螺儀資料不是在反駁撕裂，是在解釋撕裂為什麼會發生。**
它說明了為什麼「總載荷不高」的情況下仍會有單點結構失效。

### 3.4　影像能講與不能講的

用 59.94 fps 原生幀做了三個量化測試：

| 測試 | 方法 | 結果 |
|---|---|---|
| 布團中央的洞是天空還是傘腔陰影 | 洞內 RGB vs 同幀同高度的乾淨天空 | **是天空**，亮度比 0.99～1.07。T+18.503 起持續存在，四周由布料完全包圍 |
| 上方大物體會不會愈離愈遠 | 以主體質心為原點（自動扣掉搖鏡） | **不會**，距離拉到約 130 px 後穩定 → 由繩索連著。那是**拖曳傘**，不是碎片 |
| 右側小物體是否脫離 | 最近鄰關聯追蹤 | **無法判定**。2～3 幀後關聯失效 |

「被布料包圍的天空色開口」與撕裂一致，但**摺疊的傘衣在投影上完全一樣**，
所以它單獨不能定案。

**碎塊追蹤在這段影片上做不到。**傘衣只有約 80 px，候選碎塊 10～30 px，
H.264 在這個位元率下把它們吃掉了。不要基於這段影片宣稱「看到布片飛走」。

### 3.5　主傘從未在氣動意義上完全張開

影像上傘布在 T+18.486 攤得最開（3443 px，長寬比 0.93），
但**那不等於充飽**：

若主傘在 41 m/s 真的滿開（10.4 m²），載荷會是 **8.8 kN = 35 g**。
ch2 在影像峰值後 **25 ms** 取樣，讀到 5.62 g。開傘衝擊的衰減時間約 100 ms，
所以「25 ms 前存在 35 g 峰值」不成立。

**主傘峰值只達滿開阻力的約 15%。**

這不但不牴觸撕裂，反而更合理：**一副只張開一部分、又在自旋的傘，
正是載荷最容易集中到少數幾條繩上的狀態。**布攤開了，但沒充飽，
受力全落在幾個角上。

## 4　★ 第二個問題：設計本身

這個和扭轉**完全獨立**，就算沒有扭轉也會發生。

主傘滿開的設計下降率是 `sqrt(2mg/(ρ·CdA)) = 6.4 m/s`，很理想。
但**開傘時的載荷取決於開傘瞬間的速度**：

| 開傘速度 | 動壓 | 滿開載荷 | 加速度 | |
|---|---|---|---|---|
| **39 m/s**（本次實際） | 844 Pa | **8.8 kN** | **35 g** | 🔴 結構不可能承受 |
| **31 m/s**（拖曳傘終端） | 533 Pa | **5.5 kN** | **22 g** | 🔴 結構不可能承受 |
| 25 m/s | 347 Pa | 3.6 kN | 14 g | ⚠ 偏高 |
| 20 m/s | 222 Pa | 2.3 kN | 9 g | ✓ |
| 15 m/s | 125 Pa | 1.3 kN | 5 g | ✓ |

主傘設計成「直接跟著拖曳傘」，而拖曳傘的終端速度是 31 m/s。
**即使一切順利、主傘等到拖曳傘完全減速才張開，載荷仍會是 22 g / 5.5 kN。**

換句話說：**這副主傘在原本的設計流程下沒有任何一個時間點是可以安全張開的。**

諷刺的是，**扭轉反而救了箭體一次** —— 它把載荷限制在 1.40 kN。
若傘衣在 41 m/s 完全張開，8.8 kN 會直接扯斷傘繩或拉爆箭身結構。

## 5　無法確定的事

誠實列出，不要在簡報裡宣稱：

| 問題 | 為什麼無解 |
|---|---|
| 扭矩的源頭（十字傘固有旋轉？倒飛的尾翼？傘袋抽出？） | 三者都能產生繞長軸的扭矩，2 Hz 遙測分不出來 |
| 累積扭轉圈數 | 取樣率不足，方向又會反轉 |
| **破壞的確切形式**（傘布撕裂？補強帶脫開？單條繩斷？） | 未回收；影像解析度不足以追蹤碎塊 |
| **哪一條繩先失效、破口從哪個角開始** | 同上 |
| 有無布片真的脫離 | 影像最近鄰追蹤 2～3 幀後即失效 |
| 開傘衝擊真峰值 | 2 Hz 取樣，1.53 kN 是**下限** |
| 是否裝有轉環、是否失效 | 未回收 |

**可以講的是「結構失效導致永久喪失阻力」，不能講的是「傘布被撕成幾片、
破口從哪個角開始」。**後者需要實體傘衣。

不過第一項有一個可用的推論：**航電板本身（裝在箭身裡）錄到了 3.2 轉/秒。**
如果拖曳傘與吊帶之間有有效的轉環，箭身不會跟著轉。所以**要嘛沒裝轉環，
要嘛轉環卡死或規格不足**。

## 6　修正方向

按優先序：

1. **拖曳傘與主吊帶之間加轉環**，規格要能在 1.5 kN 載荷下自由旋轉。
   這是整條因果鏈的**起點**，也是唯一可以用一個零件擋掉的環節 ——
   沒有自旋就沒有載荷集中，沒有載荷集中就沒有單點結構失效。
2. **主傘不可以直接跟著拖曳傘。**兩種做法擇一：
   - **雙段式**：拖曳傘先降到 ≤20 m/s，主傘延遲到 200–300 m 再開
   - **收口（reefing）**：主傘先以縮口狀態張開，數秒後解除
   本次的設計兩者都沒有。
3. **拖曳傘偏小。**0.43 m² 的 CdA 給 25.4 kg 得到 32 m/s。
   要降到 20 m/s 需要約 **1.1 m²**（約 2.5 倍）。
3b. **檢討傘衣的補強配置。**既然失效是載荷集中造成的單點破壞，
   下一副傘的傘繩接點、補強帶、傘裙帶就必須按「單條繩承受總載荷的
   數倍」來設計，而不是按「總載荷 ÷ 繩數」。這是這次最直接的設計教訓。
4. **提高遙測取樣率或至少對衝擊事件做峰值保持。**本次兩次衝擊各只有一塊板
   錄到，純屬運氣。加速規的峰值保持暫存器成本近乎為零。
5. 陀螺儀滾轉率是**極便宜且極有效的回收系統健康指標**。
   在遙測封包裡直接送出 `|w|`，飛行中就看得出扭轉。
