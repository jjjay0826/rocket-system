# flightdata/ — 原始遙測記錄

**這是整個專案唯一無法重製的東西。**其他所有分析產出（CSV、圖表、影像幀）
都可以從這些檔案 ＋ `tools/` 重跑出來，但這些檔案本身沒有備份來源。

地面站收到什麼就存什麼，**沒有經過任何處理**。

### ★ 為什麼 `_utc` 那兩個最重要

兩塊板各自以「**自己**判定離架的瞬間」為時間原點，而它們判定的時刻差了 **0.49 秒**
（ch1 較晚）。所以兩份 log 的 `T` 欄位**不能直接比對**。

`_utc` 版本在每行前面多了地面站收到封包時的 UTC 時戳，**這是唯一能把兩塊板放到
同一條時間軸上的東西**：

```
16:57:25.560 T7087226 SQ14166 AX-0.983 AY+0.011 AZ-0.011 ...
└─ 地面站 UTC ─┘ └────────── 火箭送出的原始封包 ──────────┘
```

2026-08-01 的整個失效分析都建立在這上面 —— 「**兩次**開傘衝擊，各只有一塊板錄到」
這個關鍵發現，沒有共同時間軸就推不出來。對齊後兩板在事件前的取樣點穩定相差 30 ms，
這同時也是對齊正確的驗證。

### 完整版有什麼額外的東西

- 發射前 93 分鐘的待機封包 —— 可以看電池電壓漂移、GPS 收斂過程
- ch1 的**空中斷電重開機**（`RST=POWER-ON`）與重開後的 41 個封包
- `raw_ch1_...5e03e520.log` 含約 5000 個損壞位元組（占 0.29%）。
  **那不是檔案壞掉，是無線電位元錯誤** —— 它本身就是鏈路品質的真實記錄，不要「修」它。

## 怎麼用

```bash
python tools/parse_raw_lora.py doc/flightdata/20260801/raw_ch1_20260801_152419_5e03e520_utc.log --out-dir out
python tools/parse_raw_lora.py doc/flightdata/20260801/raw_ch2_20260801_152419_5e03e520_utc.log --out-dir out
python tools/flight_report.py out/raw_ch1_*_parsed.csv out/raw_ch2_*_parsed.csv --out report.png
```

**第一個參數放先失聯的板（ch1）**，第二個放涵蓋全程的（ch2）。
完整說明見 [`../../tools/README.md`](../../tools/README.md)。

封包欄位的意思見 [`../getting_started.md`](../getting_started.md) 第六節。
