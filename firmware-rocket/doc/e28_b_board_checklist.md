# B 板 E28-2G4T27SX(2.4GHz)換裝定案文件

> 2026-07-20 定稿。依據:E28-2G4T27SX User Manual(Ebyte)、Netlist_Schematic1_2026-06-26、
> 雙 AI 交叉驗證(Claude + ChatGPT)。
> **動機:雙板熱備援若同用 900MHz 段會互擾(同艙近距強信號前端阻塞),
> A 板留 E22-900T22D(922.125MHz)、B 板改 E28(2.4GHz)= 零互擾 + 頻率分集冗餘。**

## 1. 硬體接線(★7 腳不夠,必須 8 條線)

| E28 腳位 | 接到 | 說明 |
|---|---|---|
| M0(pin 16) | GND | 透傳模式 = 0 |
| M1(pin 15) | GND | 透傳模式 = 0 |
| **M2(pin 17)** | **4.7k~10kΩ 上拉到 3V3** | ★第 8 條線。透傳=`M2:1 M1:0 M0:0`;**M2=0=低功耗睡死**。手冊未保證內部上拉,飛行環境不可賭懸空;**不可拉 5V**(控制/通訊電平以 3.3V 為準,手冊警告 5V TTL 燒毀風險) |
| RXD(pin 14) | STM32 PA9(USART1_TX) | 即 netlist `LORA_TX` |
| TXD(pin 13) | STM32 PA10(USART1_RX) | 即 netlist `LORA_RX` |
| AUX(pin 12) | STM32 PB9 | 韌體存活檢查 + flow control 沿用(input+pulldown) |
| VCC(pin 11) | +5V | 去耦見 §5 |
| GND(1/8/10/18/20/21) | GND,**至少接 2~3 支** | RF 模組單 GND 回流差、雜訊大 |
| NC(2~7、9、22) | 接地 | 手冊明文「cannot be floated, can be grounded」 |
| ANT(pin 19) | 2.4GHz 天線,50Ω | 見 §8 上電守則 |

- 封裝:SMD 郵票孔 1.27mm(40.5×25mm),**不是** E22 的 DIP 排針 —— 需轉接板或改版 PCB。
- 900MHz 天線(火箭端+地面 9dBi)在 2.4G 完全失配,**整套換新**。

## 2. 模組配置(對照手冊 §7.5)

| 參數 | 值 | 理由 |
|---|---|---|
| 頻道 CHAN | **0x4B = 2475MHz**(主候選) | 預設 0x13=2419MHz 落在 WiFi ch1 頻寬內。2475 在 WiFi ch11(~2472)之上、BLE 廣播 2480 之下。**非保證乾淨:WiFi ch12/13、40MHz 寬頻、BLE data channel 遍佈全段 → 備 2~3 個候選頻道,比賽當天用 E28 RSSI 模式現場掃頻選定** |
| Air rate | 10k(預設) | 需求 ~2.4kbps,餘裕 4 倍 |
| 功率 | 火箭端 27dBm;**地面端若配 9dBi 天線 → 23dBm**(增益扣減後 27dBm 頂限零餘裕) |
| 地址/NETID | 0x0000(預設) | 與 A 板不同頻段,不互收 |
| LBT(OPTION bit3) | 先關;實測丟包高再開 | 2.4G 髒環境的武器,E22 沒有 |
| UART | 9600 8N1(預設) | 與韌體一致 |

配置方式二選一:
1. M 腳全拉高(**111** = 配置模式;手冊 §7.3/7.4 寫 010 是排版錯誤,勿信)+ 上位機/C0 命令;
2. **透傳模式下發 `E2 E2 E2`(HEX)開 10 秒配置窗**(E22 沒有的功能,M 腳綁死也能配)。

## 3. 韌體相容性 —— 零改動

- 透傳 UART + AUX 語意(上電低 → 自檢完拉高;**高=閒置,低=忙**;手冊 5.6.2「AUX=1 means busy」為文字錯誤)與 E22 同構。
- `lora_e22.c`(含行重組修復、AUX 存活檢查)、ManualDeploy、MSG 協定**全部直接沿用**。
- 建議差異化:**B 板發射週期 500ms → 470ms** —— 兩板獨立時鐘無法固定錯相,異週期讓相位持續滑動、不鎖死在最壞重疊(main.c 的 LoRa 節拍一行參數)。

## 4. 法規(LP0002,2400~2483.5MHz)

- 數位調變設備傳導功率上限 1W(30dBm);**天線 >6dBi 逐 dB 扣減** → 27dBm+9dBi 剛好頂限(名目 EIRP 36dBm),無餘裕 → 發射端配 9dBi 時降 23dBm。
- 2475MHz 中心 + LoRa 最大 1625kHz 頻寬 ≈ 延伸至 2475.8MHz,距 2483.5 上界安全。
- **⚠ 未結案:6dB 頻寬 ≥500kHz 條款適用性** —— SX1281 LoRa BW=203k/406k/812k/1625kHz,10k 檔實際 BW 手冊未公開、很可能 <500kHz = 920MHz 段的頻寬灰色地帶在 2.4G 重演。**行動:向 Ebyte 索取 10k 檔調變頻寬/測試報告**;不合則改大 BW 檔位(50k/100k/FLRC)或比照 920MHz 寄信查證。
- **⚠ NCC 型式認證**:FCC/CE ≠ NCC。E22 與 E28 同有此議題,隊上合規決策層面處理。

## 5. 供電去耦(27dBm 發射峰值 ~500mA,漣波要求 <100mV)

- E28 VCC 旁:**100nF + 1µF + 10~22µF(MLCC 階梯)+ 220~470µF(低 ESR 電解/聚合物)** —— MLCC 吃高頻尖峰、大電容吃慢變化,不可互相取代。現板 `C_LORA` 100nF 遠遠不足。
- SD 卡旁另配 100nF + 10~47µF;E28 與 SD **星狀分支供電**,必要時 E28 支路加磁珠。
- 驗收:示波器**量元件腳位**(E28 VCC、SD VCC)的發射瞬間壓降,不是量穩壓器輸出端。

## 6. 同艙雙發射機互擾對策

- 諧波安全:922.125×2=1844.25、×3=2766.4MHz,皆不落 2.4G 段 ✓。
- 真正風險:前端阻塞/LNA 壓縮/寬頻底噪/共電源傳導(10cm 內場強極高,頻段不同也會 desense)。
- 對策:異週期發射(§3)、天線分置艙體兩端+正交、RF 走線分開;濾波器視實測加(須耐 22~27dBm 發射功率,勿用接收級小功率 SAW)。
- **放飛前必測:同艙滿功率互擾測試**(兩板同時全功率發,量各自地面鏈路丟包率)。

## 7. 電火頭(順帶定案,與 E28 無關)

- Netlist 點火路徑 `+7V → Q5/Q7/Q9 → 7V_OUT 直出`,**無限流電阻**(22Ω 是感測器線 R23/R24,曾誤傳)→ 電火頭電流 ≈ 3~5A,遠超常見 all-fire(0.75~1.25A),**1 秒脈寬充裕**。
- 放飛前仍須:確認電火頭型號 all-fire 規格 + 多顆實際地面點火驗證。

## 8. 桌測順序與上電守則

1. **★天線先接再上電** —— 27dBm PA 無載(或接 900M 天線)發射會被反射功率打壞;首測可先配 17dBm。
2. 上電觀察 AUX:**先低後高** = 活著;恆低 = 查 M2 上拉。
3. 配置頻道/功率(§2)→ 兩台 E28 對傳測透傳。
4. 接航電板跑現有韌體:MOD bitmask 的 LoRa 位應直接亮、遙測直接通。
5. 放飛前驗證:同艙互擾(§6)、最低電池電壓+低溫供電、SD 寫入+發射最差負載、電火頭實點(§7)。
